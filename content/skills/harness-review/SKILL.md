# Harness Review

Repository content/assets/adapters/manifest are source; installed homes are generated output.
Inspect the requested scope and project instructions. Review alone authorizes diagnosis, not
source fixes or live installation.

Check selected-target model/effort/permissions, parsed TOML/JSON, skill frontmatter, references,
helper dependencies, ownership preservation, protected paths, secret/scope handling and custom homes.
Distinguish intentional compatibility content from accidental runtime dependencies.

Use supported runtime UI/tools and redacted controller receipts for observed routing/review/hook
behavior. Missing telemetry does not prove dead functionality. Do not depend on private rollout
formats or enumerate histories. User-provided logs require sample limits and secret redaction.

An independent bounded read-only explorer/reviewer is optional. Give concrete findings with
file/line evidence, consequence and scoped fix. If fixes were authorized, modify canonical repo
files and validate a temporary target install. Live home changes, CLI updates and publication
require their own authority.
